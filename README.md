# continual-knowledge-lora

Teach an LLM new facts in steps and measure what it forgets.

Qwen2.5-7B-Instruct learns three "books" one after another: book A, then B, then C. After every
step I measure how much of the new book it learned, how much of the old books it kept, and whether
general skills (MMLU) moved. Three ways to add a book are compared on the same data and seeds:

| method | what it does |
|---|---|
| `naive` | a new LoRA adapter for the new book, trained on top of the current model |
| `kl` | the same, plus a KL penalty to the previous model on 300 replay lines from earlier books |
| `router` | the model after book A stays frozen; each new book gets its own expert adapter, and a learned router (a linear head on a middle-layer hidden state) decides per question which expert to switch on |

The router reads the plain question, without the book name. It is part of the model; nothing
outside the model chooses the expert.

## Data

Each book holds 40 fictional people with 4 facts each (birth town, profession, birth year,
mentor): 160 facts. The facts are generated by code from a fixed seed, so the base model cannot
know them (see the `base` row) and no training text comes from another language model.

The books are close in topic on purpose: different people, but the same relations and the same
towns and professions. That is the hard case for continual learning, because the update for a new
book lives in the same input space as the old one.

Per fact, training has 6 paraphrased statements and 4 question-answer pairs; per person, 2 short
biographies. Each fact is tested with one question in a wording that never appears in training
(see `TEST_QUESTIONS` in `src/ckl/books.py`), so the score measures stored knowledge, not memorised
wording. An answer counts only if it contains the exact value.

## Metrics

- **book A / B / C**: correct key answers out of 160, mean over 3 seeds, worst seed in brackets.
- **book A kept**: of the book-A questions the model answered correctly after step 1 (M1), the share
  still answered correctly after the later steps.
- **MMLU**: 300 test questions (fixed sample), zero-shot, letter with the highest logit.
- **router**: share of held-out prompts sent to the right place, including GSM8K test questions,
  which the router never saw in any form.
- Every score in the JSON files has a 95% Wilson interval; per-question correctness is stored, so
  any other cut can be computed from `runs/`.

How to read it:

- `book A kept` is of the book-A questions that M1 answered correctly. `book B kept` is of the
  book-B questions that were correct after step 2.
- `naive` shows the problem: the new adapter overwrites what the old one stored.
- `kl` and `router` are the two ways of keeping it. `kl` pays with a small loss on the older books
  and with slower training; `router` pays with routing mistakes (table below).

After three steps, `naive` keeps 74 of 160 book-A answers and 111 of 160 book-B answers (mean of 3 seeds), `kl` keeps 153 and 155, and `router` keeps 160 and 160 in every seed. Both `kl` and `router` learn each new book fully (160 of 160). On MMLU (300 questions) M1 scores 0.656 and `router` 0.656 (the same), while `naive` and `kl` score 0.650. Training one adapter takes about 15 to 30 minutes on the L4 (`naive` book B 18 minutes, `router` expert 17.5 minutes), and `kl` is about 1.6 times slower than `naive` (28 minutes for book B), so a full seed with all three methods takes about 161 minutes. The 100% routing is the easiest case: every person appears in only one book, so the router can learn names, and these numbers do not show that routing holds when books share entities. Before book C is trained, only 4 to 7% of book-C questions are routed to "none"; the rest go to an expert, so this router does not recognise a book it has not seen.

## Reproduce

```bash
uv sync
uv run pytest -q                          # unit tests, CPU only
uv run ckl-run --smoke --out runs/smoke   # tiny model, checks the pipeline on a laptop
uv run ckl-run --check --eval-bs 8 --out runs/main   # 7B: base model and book A only, first seed
uv run ckl-run --eval-bs 8 --out runs/main           # 7B: everything, seeds 0 1 2
uv run ckl-report --out runs/main         # writes runs/main/results.md
```

`--eval-bs 8` is for a 24 GB card (the default of 32 runs out of memory in the MMLU evaluation).
Training peaks at about 21 GB. On a 48 GB card the default works. Results are written to
`runs/main/results_seed<k>.json` after every evaluation, so a crash keeps what ran.

The model revision is pinned (`a09a35458c702b33eeacc393d103063234e8bc28`). Adapters are saved to
`runs/main/adapters/`; the run log, timings and peak memory per adapter are in the JSON files.

## Limits

- Synthetic facts are simpler than real books: short, fixed relations, distinct names.
- People never appear in two books. In a real series the same characters come back, and a router
  that decides from the question alone would be less accurate.
- The router picks one expert per question (sequence level). Facts that need two books in one
  answer are not tested.
- The router's "no expert" examples come from MMLU validation and dev questions. That is fine for this demo, but a real package must not use any public benchmark data (MMLU, IFEval, GSM8K) for the router, because those sets are test sets.
- The router runs in two passes (hidden state first, then the chosen expert). Loading it inside a standard evaluation harness needs one forward pass; this repo does not do that.
- Honesty (made-up answers to false-premise questions) is not measured here.
